# iPhone Companion: Backburner

The **Speed / Aumenta velocità** page integrates [Backburner by StayLameBro](https://github.com/StayLameBro/backburner). It is mutually exclusive with Companion's existing subagent runtime. The Mac selector is in **Tools → iPhone**. A compatible wired iPhone must be present before the speed option appears; after a disconnect the selected mode remains visible so you can return to Agent.

## Requirements and first use

1. Use Apple Silicon and macOS 14 or later for acceleration (the rest of the Mac app retains its macOS 12 deployment target). The original reference configuration is a 24 GB M4 Pro MacBook Pro and an A19 Pro/A18 Pro iPhone. The Companion app requires iOS 18.6 or later. An iPhone must negotiate USB at **10 Gb/s or faster**; ordinary USB 2 iPhone cables and non-Pro models with USB 2 cannot enable this mode. Thunderbolt certification alone is not the check.
2. Install Companion 0.0.4 by signing/sideloading its IPA. Preserve the `com.apple.developer.kernel.increased-memory-limit` entitlement, as in the original Backburner app. Keep the phone unlocked and Companion in the foreground.
3. Obtain the **Qwen3.8-27B GGUF or a compatible derivative (including abliterated/uncensored)** and **a compatible Qwen3.8-27B DFlash2 GGUF** (the original `dflash2-v2-q4km-self16.gguf` or a compatible quantization), following the pinned upstream README and model preparation instructions in `studio/backend/vendor/backburner`. Weights are not included. Quantization is checked per tensor: mixed/dynamic quantizations such as UD and GSQ keep their exact weights; filename and `general.file_type` do not gate compatibility.
4. On Macs with at least 24 GiB RAM, the original 64k q8 profile keeps upstream’s 20,000 MiB GPU wired-limit prerequisite. Follow upstream’s `sudo sysctl iogpu.wired_limit_mb=20480` after reboot only on a sufficiently large Mac; Unsloth never applies it automatically. On 16–23 GiB Macs, the memory-saving profile uses mmap, up to 8k local q4 KV cells, one recurrent checkpoint, batch/ubatch 128/64 and up to three speculative draft tokens. Its split-prefill minimum is 64 offloaded tokens: upstream keeps the last 64-token microbatch on Mac, so a complete 128-token batch can send the other 64 to iPhone. The original 512-token minimum would disable all splits at this batch size. This setting is part of the launch/cache identity. The selected total context (including 50k) is retained; older KV moves to the phone after the local cache fills. A draft that exceeds the estimated GPU budget runs on CPU using the upstream shared target head. RAM and GPU budgets are checked before replacing the resident model. `iogpu.wired_limit_mb=0` means the automatic cap, not zero GPU memory.
5. On iPhone open **Speed → Increase speed**. This drains and unloads the subagent before starting Backburner. On Mac open **Tools → iPhone → Prepare iPhone**, keep the current target path and select a downloaded DFlash2 from the menu (or enter a local GGUF path), and choose **Prepare and copy over USB**. The exact upstream split script uses L40 for iPhone18,* (A19 generation), L52 otherwise, and drops optional MTP blocks. Larger weights move the split later in multiples of four to fit conservative 6/3 GiB tail-weight budgets; it copies the tail, original 16k ANE template, and source identity through upstream's USB transfer protocol.
6. When copying finishes, turn Increase speed off and on on the phone, then wait for the tail to load. Load the same Qwen GGUF on Mac and select **Increase speed** in Tools. Changing modes requires idle Mac inference and no running/queued Companion tasks. Select **Agent** to reload the standard Mac engine and restore your Companion preferences.

## Interchangeable target weights

Supported weight types in the pinned Metal engine: F32, F16, BF16; Q1_0, Q2_0, Q4_0, Q4_1, Q5_0, Q5_1, Q8_0; Q2_K, Q3_K, Q4_K, Q5_K, Q6_K; IQ1_S/M, IQ2_XXS/XS/S, IQ3_XXS/S, IQ4_NL/XS; MXFP4 and TQ2_0. File-level labels such as Q4_K_M or IQ3_M are mixtures of these tensor types. NVFP4 and TQ1_0 lack the required Metal kernels in this engine and are rejected before transfer; intermediate Q8_1/Q8_K and integer/F64 weights are also rejected. Formats accepted by the validator still require enough Mac/iPhone memory. Merge sharded GGUFs into one file before preparation.

Compatibility requires Qwen3.8 ancestry in model metadata, 64 trunk layers (additional MTP layers are excluded from the tail), and the original 27B dimensions, attention/GDN geometry and four-layer full-attention interval. The embedding/output vocabulary stays at 248,320 tokens for the original draft; derivatives that resize it are rejected. Other Qwen sizes/architectures are not covered. DFlash2 drafts are checked by architecture, 27B dimensions, the five target-layer hooks, convolution/selector shapes, complete required tensors, supported Metal weight types, and matching target vocabulary/tokenizer. The filename and file-level quantization label do not gate compatibility. The local menu scans completed GGUFs in known HF caches, model folders, LM Studio and configured scan folders, deduplicating snapshots of the same file. It never downloads weights. Validated examples are [HermiHg’s 535 MiB mixed draft](https://huggingface.co/HermiHg/Qwen3.8-27B-DFlash2-Q2_K_S-MIX-GGUF) and the [nerkyor repository’s 1,090 MiB Q4_K_M DFlash2](https://huggingface.co/nerkyor/Qwen3.8-27B-EfficientThink-Uncensored-K3-Opus5-Grok4.6-GPT5.6Sol-SFT-SimPO-DFlash2-GGUF). A repository ID is not a local file path. Draft weights retain their exact quantization; acceptance rate may differ for fine-tunes. No conversion to IQ4_XS or replacement/download of the selected target occurs. The upstream SME matrix optimization applies only to IQ4_XS tensors; other weight types use the upstream Metal path. The ANE attention template operates on KV and is independent of target weight quantization.

To change weights, return to Agent, load the desired compatible GGUF on Mac, prepare/copy that GGUF's tail, restart Speed on iPhone, then enable Increase speed on Mac. A source SHA mismatch blocks acceleration until both devices use the same weights.

## Original behavior and integration boundaries

The original profile invokes unmodified upstream `serve.sh` with its original defaults: 64k local q8_0 KV, one slot, DFlash2 plus n-gram speculation, original Metal/SME kernels, split prefill, phone-held KV, and the original SSD prompt-cache proxy. Remote context is sized using upstream's 9,400 MiB wired ceiling and 512 MiB app reserve, capped at 262,144 tokens.

While context fits in the local cache (64k in the original profile; up to 8k in the 16 GiB profile), the phone accelerates sufficiently long prompt reads. Beyond the local threshold the phone holds old KV and computes attention using its GPU/Neural Engine. 64k is not a minimum required total context. The smaller profile changes cache precision/residency and speculative width, using existing upstream options; it is not numerically identical to the original q8 cache profile. The original automatic 60-second phone fallback and algorithmic limitations are preserved. Performance numbers in the upstream README are upstream measurements, not measurements of this integration.

The selector controls one wired iPhone per Mac session. Upstream's separate experimental generic RPC/phone-draft/FFN modes and multi-phone command-line orchestration are not exposed. The integrated function offers the upstream default and a memory-saving configuration of the same pinned engine, not a general-purpose accelerator for arbitrary models.

Unmodified upstream sources and their SHA-256 checksums are in `studio/backend/vendor/backburner/UPSTREAM.json`. Backburner is pinned at `c78e38b6bf74c5672aaaf5c66668b6540b97bd37`; its llama.cpp engine is pinned at `f8c76832b9bb7710db52143d9c89adcda5402718`. MIT licenses and attribution are included in the Mac backend and iPhone notices/page.

The native adapter changes service ownership, cancellation, USB-only listener binding, environment restoration and sandbox paths to `Documents/Backburner`. Its compute kernels and binary wire protocols remain upstream code. The Mac build applies `backburner-mac-remote-shutdown.patch` to join the remote-attention thread at process exit, before its static mutex and queue are destroyed; the original detached thread could abort during shutdown after remote KV was used. The patch changes thread ownership only and is recorded by name/SHA-256 in the runtime manifest. It is reversed before building the iPhone framework. The private Backburner framework exports only its Objective-C bridge, preventing C-symbol collisions with Companion's existing llama.cpp. The simulator adapter explicitly reports unavailable acceleration.

The Mac runtime is bundled in the release, verified against its manifest, and installed under `<studio root>/backburner/<pinned engine commit>/runtime`. The standard llama.cpp updater uses a different directory and cannot overwrite this engine. Its models, draft setting and cache also live separately. SSD prompt/KV caches are isolated by target content SHA-256, draft file identity and the complete launch profile; switching quantization or fine-tune cannot reuse another model's states. Switching to Agent restores the caller's original Mac load settings.

## Build and validation

Run `unsloth-companion/scripts/build_backburner_runtime.sh` before building the Mac app or IPA. It fetches the pinned engine and generates the private device/simulator framework and Mac binaries. For the original ANE template set `UNSLOTH_BACKBURNER_COREML_PYTHON` to a build-only Python environment with `coremltools==9.0` and `numpy==2.2.6`. No such build tooling is needed by end users.

Backend tests: `studio/backend/tests/test_backburner_companion.py`. Native lifecycle regression: `python3 unsloth-companion/scripts/test_backburner_lifecycle.py` after the runtime build. The latter uses actual TCP clients and the generated native adapter on macOS; only the endpoint, sandbox home and iOS-only available-memory query are substituted. It verifies three start/stop cycles, open clients, closed ports, protocol version and environment restoration. It does not test phone inference.

The release includes build and automated-test evidence. On an actual M2 Pro with 16 GiB RAM and automatic GPU cap, the installed Huihui Qwen3.8-27B IQ3_XXS generated a nonempty 24-token completion with both downloaded drafts: HermiHg on GPU and nerkyor Q4_K_M on CPU, with 8k local q4 KV and no kernel limit change. These short Mac-only checks do not benchmark long-context speed or verify a filled 50k context. The physical iPhone was disconnected during these checks. Transfer, remote attention beyond the 8k threshold and full Mac/iPhone performance remain acceptance checks; the release is a prerelease.

Release mlx.41 USB acceptance: with the actual 16 GiB M2 Pro, installed IQ3_XXS target, nerkyor Q4_K_M CPU draft and 10 Gb/s iPhone link, the same 1,580-token prompt sent zero tail chunks at minimum 512 and 12 chunks at minimum 64, producing the same answer. Prompt processing was 57.03 versus 57.72 tok/s in this single cold comparison; it does not establish a general speedup. A separate 8,972-token prompt sent 64 more chunks, held 4,096 remote keys and made 240 phone-attention calls. The latter exposed the Mac thread-exit defect addressed by the lifecycle patch; final rerun and shutdown evidence are in MLX41-VERIFICATION.json. Full 50k acceptance and comparative decode benchmarks remain unverified.
